# Security Policy

This is a public-source, pre-release research PoC. Public availability does not constitute a production deployment, software release, or operational approval. The project does not promise enterprise security controls, continuous monitoring, or a response SLA.

## Sensitive Material

Never submit credentials, API keys, bearer tokens, private keys, connection strings, signed URLs, SAS query parameters, private data, confidential operational information, full exploit details, local environment files, model API response caches, or machine-specific absolute paths in public issues, pull requests, logs, examples, commits, or CI output. Signed retrieval URLs may exist only in process memory and must be redacted before logging or provenance capture.

Full runtime directories, raw HTTP responses, raster assets, and AOI chips remain ignored until licensing, disclosure, and secret review are complete. Do not delete local evidence merely because it is ignored.

## Reporting

Report a suspected leak privately to the repository owner. Use GitHub private vulnerability reporting if it is available for this repository; otherwise use a private channel. Do not open a public issue or pull request, or paste sensitive material or full exploit details into chat, logs, examples, commits, or CI output. Rotate exposed credentials before history remediation.

No security support window or public vulnerability disclosure programme is promised. Public source visibility does not authorize disclosure of sensitive material or imply production security readiness.
