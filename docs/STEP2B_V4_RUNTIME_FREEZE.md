## Frozen Execution

The runtime verifies the clean Git baseline, exact detached approval, policy bytes, runtime-spec bytes, implementation-file hashes, CPython version, and exact NumPy/Rasterio versions before network access. Version `1.1.1` retains at most three attempts per request with frozen delays of 0, 2, and 5 seconds. It treats raw or `urllib`-wrapped connection resets, `RemoteDisconnected`, connection errors, and timeouts as transport failures while leaving programming, JSON, schema, and metadata-semantic errors non-retryable. Exhausted transient transport failures remain `SOURCE_UNAVAILABLE`.

Before each request, the runtime persists one authoritative network-attempt event containing a safe request-identity hash, event ID, timestamp, source category, operation, and per-request attempt number. The ledger is authoritative; run state, failure records, and provenance reuse its event ID and timestamp instead of generating replacement timestamps.

The live sequence is:

1. retrieve and verify CER project and CEA sources;
2. complete both frozen STAC searches without a cloud predicate;
3. apply the 200-item metadata inventory limit;
4. fetch signed product/granule metadata without persisting credentials;
5. resolve representations, metadata admissibility, and independent acquisitions;
6. apply the 40-acquisition gate before raster pixels;
7. process all admissible groups on the frozen AOI grid;
8. calculate coverage, NDVI aggregation, primary disposition, and separate sensitivities;
9. seal the canonical assessment;
10. recompute NDVI and disposition from unsigned AOI-level B04/B08/SCL caches in explicit offline replay mode;
11. validate provenance, scan outputs, and write checksums.

Any implementation or deterministic processing failure is preserved and cannot resume under the same run ID. The runtime does not start Step 3.
